# iOS Build Pipeline Updated for CocoaPods

I have updated the GitHub Actions workflow to support the new CocoaPods integration. This ensures that the CI/CD pipeline correctly handles the Firebase dependencies and the renamed Gradle tasks.

## Changes Made

### [CI/CD Workflow]

#### [.github/workflows/ios-build.yml](file:///C:/Users/yoga/Desktop/New/FireAndSafty/.github/workflows/ios-build.yml)

- **CocoaPods Installation**: Added a step to install CocoaPods on the GitHub runner using `sudo gem install cocoapods`.
- **Updated Gradle Task**: Changed the framework linking task to `:shared:linkPodDebugFrameworkIosArm64`. This is the new task name generated by the `native.cocoapods` plugin.
- **Pod Install Step**: Added a `pod install` step inside the `iosApp` directory to generate the `.xcworkspace` and link the shared framework with native dependencies.
- **XcodeBuild Update**: Switched the `xcodebuild` command to use the generated **workspace** (`iosApp.xcworkspace`) instead of the project file. This is mandatory after running `pod install`.
- **Artifact Path Update**: Updated the upload path to point to the new location of the generated framework under `shared/build/cocoapods/framework/`.

## Why this is necessary
1.  **Ambiguity Resolved**: The CocoaPods plugin replaces the default `:shared:linkDebugFramework...` tasks with `:shared:linkPodDebugFramework...` tasks. CI must use the specific new name.
2.  **Dependency Linking**: CocoaPods is now responsible for linking the Firebase iOS SDK symbols (like `FIRAuth`) into your app. Without `pod install` in the CI, the linker would still fail.
3.  **Modern Workflow**: This aligns your project with the standard Kotlin Multiplatform + CocoaPods pattern, making it easier to add more iOS-specific libraries in the future.
